## 1. คำถอดความและบทบรรยายสำคัญ (Core Lecture Transcripts)

### 1.1 วงจรชีวิตของ Transaction และสถานะ (Transaction States)
> "Transaction เมื่อเริ่มต้นทำงาน จะอยู่ในสถานะ Active... มีการประมวลผลคำสั่งทีละคำสั่ง ถ้าทุกคำสั่งทำงานสำเร็จครบถ้วน ก็จะเข้าสู่สถานะ Partially Committed และเมื่อข้อมูลทั้งหมดถูกเขียนลงใน Disk เรียบร้อยแล้ว ก็จะเข้าสู่สถานะ Committed อย่างสมบูรณ์ แต่ถ้ามีคำสั่งใดคำสั่งหนึ่งล้มเหลว หรือเกิดข้อผิดพลาดระหว่างทาง ระบบจะเปลี่ยนสถานะเป็น Failed ทันที และ DBMS จะต้องทำการ Rollback หรือ Undo คืนค่าเดิมทั้งหมดจนกลายเป็น Aborted..."

### 1.2 คุณสมบัติ ACID Properties
> "คุณสมบัติสำคัญที่สุดของ Transaction ที่ทุกคนต้องจำและเข้าใจอย่างถ่องแท้ คือ ACID:  
> - **Atomicity (ความเป็นหนึ่งเดียว):** ทั้งหมดหรือไม่ทำเลย (All or Nothing) ถ้ามี 10 คำสั่ง ทำสำเร็จ 9 คำสั่ง แล้วคำสั่งที่ 10 ล่ม ทั้งหมดต้องถูกย้อนกลับ (Rollback) เสมือนไม่เคยเกิดขึ้น  
> - **Consistency (ความถูกต้องของข้อมูล):** ผลรวมของเงินในระบบต้องเท่าเดิม เช่น ก่อนโอนเงิน บัญชี A มี 1,000 บัญชี B มี 500 รวมเป็น 1,500 บาท เมื่อโอน 200 บาทแล้ว บัญชี A เหลือ 800 บัญชี B มี 700 รวมกันก็ต้องได้ 1,500 บาทเท่าเดิม  
> - **Isolation (การแยกตัวโดดเดี่ยว):** ในเวลาเดียวกันมีคนใช้งานเป็นร้อยเป็นพันคน แต่ระบบต้องจัดการให้แต่ละ Transaction ทำงานเสมือนอยู่คนเดียว ไม่ให้ผลการทำงานระหว่างทางที่ยังไม่ Commit ไปรบกวนคนอื่น  
> - **Durability (ความคงทนถาวร):** เมื่อขึ้นคำว่า Transaction Committed แล้ว แม้ไฟจะดับ เครื่องจะดับ หรือเซิร์ฟเวอร์จะล่มในวินาทีถัดไป ข้อมูลนั้นต้องไม่หายเด็ดขาด"

### 1.3 ปัญหาที่เกิดจากการทำงานพร้อมกันโดยไม่มีการควบคุม (Concurrency Problems)
> "ถ้าเราปล่อยให้หลาย Transaction เข้ามาอ่านและเขียนข้อมูลพร้อมกันโดยไม่มีการล็อก จะเกิด 3 ปัญหาใหญ่:  
> 1. **Lost Update (ปัญหาการอัปเดตสูญหาย):** เช่น ต่างคนต่างอ่านยอดเงิน 1,000 บาท คนแรกถอน 200 เหลือ 800 คนที่สองถอน 300 แล้วเขียนทับกลายเป็น 700 ยอดของคนแรกจึงสูญหายไป  
> 2. **Uncommitted Dependency / Dirty Read (การอ่านข้อมูลขยะ/ข้อมูลที่ยังไม่ยืนยัน):** Transaction ที่สองเข้ามาอ่านข้อมูลที่ Transaction แรกแก้ไขอยู่ แต่บังเอิญ Transaction แรกเกิด Error แล้ว Rollback คืนค่าเดิม ทำให้ข้อมูลที่ Transaction สองเอาไปใช้ผิดพลาด  
> 3. **Inconsistent Analysis (การวิเคราะห์ข้อมูลที่ไม่สอดคล้องกัน):** เกิดจากการที่ Transaction หนึ่งกำลังคำนวณผลรวมของหลายๆ บัญชี แต่มีอีก Transaction เข้ามาโอนเงินระหว่างบัญชีก่อนที่การรวมจะเสร็จ ทำให้ยอดรวมคลาดเคลื่อน"

### 1.4 กลไกการล็อกและ Lock Compatibility Matrix (ออกสอบควิซ!)
> "เพื่อแก้ปัญหาข้างต้น เราจึงต้องมีสิ่งที่เรียกว่า การล็อก (Locking):  
> มี 2 ประเภทหลักคือ Shared Lock (S) และ Exclusive Lock (X)  
> - **Shared Lock (S) หรือ Read Lock:** ใช้เมื่อต้องการ 'อ่าน' ข้อมูลเท่านั้น ไม่อนุญาตให้แก้ไข ข้อดีคือหลาย Transaction สามารถขอ S-Lock บนข้อมูลเดียวกันได้พร้อมกัน  
> - **Exclusive Lock (X) หรือ Write Lock:** ใช้เมื่อต้องการ 'แก้ไข' ข้อมูล (Insert, Update, Delete) ใครถือ X-Lock อยู่ คนอื่นจะเข้ามาขออ่าน (S) หรือขอเขียน (X) ไม่ได้เลย ต้องรอจนกว่าจะ Release Lock  
>  
> **ตาราง Lock Compatibility Matrix:**  
> - ถ้าคนแรกถือ S แล้วมีคนมาขอ S -> ตอบ **Yes** (ให้อ่านพร้อมกันได้)  
> - ถ้าคนแรกถือ S แล้วมีคนมาขอ X -> ตอบ **No** (ห้ามเขียนทับข้อมูลที่กำลังอ่าน)  
> - ถ้าคนแรกถือ X แล้วมีคนมาขอ S -> ตอบ **No** (ห้ามอ่านข้อมูลที่ยังแก้ไม่เสร็จ)  
> - ถ้าคนแรกถือ X แล้วมีคนมาขอ X -> ตอบ **No** (ห้ามเขียนพร้อมกันสองคน)  
> ถ้าตอบ No หมายถึง Transaction นั้นต้องรอ (Wait) จนกว่าเจ้าของเดิมจะปลดล็อก"

### 1.5 Two-Phase Locking (2PL) และ Deadlock
> "การล็อกต้องมีวินัย เราใช้กฎ **Two-Phase Locking Protocol (2PL)**:  
> 1. **Growing Phase (ระยะขยาย):** ขอ Lock ได้เรื่อยๆ แต่ห้ามปลด Lock ใดๆ  
> 2. **Shrinking Phase (ระยะหด):** ปลด Lock ได้เรื่อยๆ แต่ห้ามขอ Lock ใหม่เพิ่มเติมอีกเด็ดขาด  
> หากจัดการไม่ดีจะเกิด **Deadlock (ภาวะติดหล่ม/ชะงักงัน):** เช่น T1 ถือ A รอ B ขณะที่ T2 ถือ B รอ A ต่างคนต่างไม่ยอมปล่อย DBMS ต้องมีระบบตรวจจับ (Deadlock Detection) โดยสร้าง Wait-For Graph และเลือกเหยื่อ (Victim Selection) 1 คนเพื่อ Rollback"

### 1.6 การกู้คืนระบบและความล้มเหลว (System Failure & Recovery)
> "เมื่อระบบเกิด Crash ขึ้นมา เราแบ่งความเสียหายเป็น:  
> 1. **System Failure (Soft Crash):** ฮาร์ดดิสก์ไม่เสียหาย แต่ RAM ดับ ข้อมูลที่ค้างใน Buffer หายไป -> กู้คืนโดยอาศัย **Log File**  
>    - มีบันทึก `[Start, T]`, `[Write, T, X, old_val, new_val]`, `[Commit, T]`  
>    - Transaction ใดที่มี `Commit` ใน Log แปลว่าผู้ใช้ทำเสร็จแล้ว -> ให้ทำ **REDO** เพื่อเขียนค่าลง Disk  
>    - Transaction ใดที่มี `Start` แต่ไม่มี `Commit` แปลว่าทำค้างไว้ตอนไฟดับ -> ให้ทำ **UNDO** ย้อนกลับเอาค่า old_val คืนมา  
> 2. **Media Failure (Hard Crash):** จานแม่เหล็กในฮาร์ดดิสก์พัง หัวอ่านขูดจาน -> Log ในเครื่องก็หาย ต้องกู้จากเทป Backup ภายนอกมา Restore"

## 2. สรุปประเด็นสำคัญสำหรับทบทวนสอบ (Key Exam Takeaways)

| หัวข้อ | จุดสำคัญที่ต้องเขียนในข้อสอบ |
| :--- | :--- |
| **ACID** | ท่องและอธิบายให้ได้ทั้ง 4 ตัว: Atomicity (All or None), Consistency (Valid State), Isolation (Independent Execution), Durability (Persistent after commit) |
| **Lock Matrix** | วาดตาราง 2x2: มีเพียงช่อง **(S, S) เท่านั้นที่เป็น Yes** อีก 3 ช่องที่เหลือเป็น **No** ทั้งหมด |
| **Crash Recovery** | ดู Log File เป็นหลัก: มีคำว่า `Commit` = **Redo** / ไม่มีคำว่า `Commit` = **Undo (Rollback)** |
