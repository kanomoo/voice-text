## 2. เจาะลึกข้อสอบควิซและแนวคำตอบที่ถูกต้อง (Quiz Questions & Master Solutions)

### ข้อที่ 1: จงอธิบายคุณสมบัติ ACID Properties ของ Transaction
- **Atomicity (ความแบ่งแยกไม่ได้ / เป็นหนึ่งเดียว):** ทุกคำสั่งใน Transaction ต้องสำเร็จครบทั้งหมด (All) หากมีข้อผิดพลาดแม้แต่จุดเดียว ระบบต้องยกเลิกและย้อนกลับ (Rollback) เสมือนไม่มีอะไรเกิดขึ้น (None)
- **Consistency (ความถูกต้องสอดคล้อง):** Transaction ต้องนำพาฐานข้อมูลจากสถานะที่ถูกต้องหนึ่ง (Valid State) ไปสู่อีกสถานะที่ถูกต้องหนึ่ง โดยไม่ละเมิด Integrity Constraints เช่น ผลรวมของเงินก่อนและหลังโอนต้องเท่าเดิม
- **Isolation (ความโดดเดี่ยวในการประมวลผล):** ในสภาวะ Concurrency แต่ละ Transaction ต้องทำงานแยกขาดจากกัน ผลลัพธ์ระหว่างทำที่ยังไม่ Commit ต้องไม่ถูกเปิดเผยให้ Transaction อื่นเห็น เพื่อป้องกัน Dirty Read
- **Durability (ความคงทนถาวร):** เมื่อ Transaction ส่งสัญญาณ `COMMIT` แล้ว ข้อมูลที่เปลี่ยนแปลงจะต้องถูกบันทึกอย่างถาวรลงในหน่วยเก็บข้อมูลถาวร (Non-volatile Storage) แม้ระบบจะล่มในวินาทีถัดไประบบก็ต้องกู้คืนข้อมูลนี้กลับมาได้

### ข้อที่ 2 พาร์ท 1: จงอธิบายตาราง Lock-based Concurrency Matrix
- **Shared Lock (S):** ใช้สำหรับคำสั่ง **Read-only** อนุญาตให้อ่านพร้อมกันได้ ดังนั้นเมื่อมีผู้ถือ S แล้วมีผู้มาขอ S อีก จึงตอบ **Yes**
- **Exclusive Lock (X):** ใช้สำหรับคำสั่ง **Write (Insert/Update/Delete)** ต้องการแก้ไขข้อมูลเพียงผู้เดียว ดังนั้น:
  - มีคนถือ S แล้วมาขอ X -> ตอบ **No** (ห้ามเขียนแทรกขณะมีคนอ่าน)
  - มีคนถือ X แล้วมาขอ S -> ตอบ **No** (ห้ามอ่านข้อมูลที่ยังแก้ไขไม่เสร็จ ป้องกัน Dirty Read)
  - มีคนถือ X แล้วมาขอ X -> ตอบ **No** (ห้ามเขียนทับกัน ป้องกัน Lost Update)
- *สรุป:* มีเพียงกรณี **(S, S) ช่องเดียวเท่านั้นที่ตอบ Yes** นอกนั้นเป็น **No** ทั้งหมด

### ข้อที่ 2 พาร์ท 2: การจัดการ 5 Transactions ใน Log File หลัง Server Crash
หลักการตัดสินใจของ DBMS เมื่อตรวจสอบ Log File หลัง System Crash:
- **Transaction ใดที่มีบันทึก `COMMIT` หรือเสร็จสิ้นก่อน Crash:**
  - **การดำเนินการ:** ต้องสั่ง **REDO (ทำซ้ำ)** เพื่อนำค่าใหม่ (`new_value`) เขียนลงใน Data File บนดิสก์ให้สมบูรณ์ตามหลัก Durability
- **Transaction ใดที่มีบันทึก `START` แต่ไม่มี `COMMIT` หรือยังค้างอยู่ตอน Crash:**
  - **การดำเนินการ:** ต้องสั่ง **UNDO / ROLLBACK (ยกเลิก)** เพื่อนำค่าเดิม (`old_value`) ย้อนกลับมาแทนที่ ป้องกันข้อมูลครึ่งๆ กลางๆ ตามหลัก Atomicity
