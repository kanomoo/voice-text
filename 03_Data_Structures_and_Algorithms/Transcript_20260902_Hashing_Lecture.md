## 1. คำถอดความและบทบรรยายสำคัญ (Core Lecture Transcripts)

### 1.1 การแก้ปัญหาการชนแบบ Separate Chaining
> "เทคนิคแรกในการแก้ปัญหาการชน (Collision) คือ Separate Chaining... ต่อให้มันชนกันยังไงก็ตาม มันก็ใส่เข้าไปได้ เพราะ Linked List มันยืด ยาว ออกมา... Separate แปลว่าแยกออกจาก Hash Table ใน Hash Table ไม่มีเลขใส่ ตัวเลขข้อมูลอยู่ที่ไหน อยู่ใน Linked List... ฝรั่งมองเหมือนต่อเป็นโซ่ ก็เลยเรียกว่า Chaining... วิธีการนี้เป็นวิธีแรกๆ ที่แก้ปัญหาการชน แต่ไม่เป็นที่นิยมใช้ในโปรแกรมประสิทธิภาพสูง เพราะต้องจัดการถึง 2 ขั้นตอน ต้องผ่าน Hash Function ก่อน แล้วก็ไปจัดการที่ Linked List อีก..."

### 1.2 การแก้ปัญหาการชนแบบ Open Addressing & Linear Probing
> "เค้าก็เลยมาวิธีที่ 2 ที่เราเรียนกันถึงสัปดาห์ที่แล้ว คือ Open Addressing... แบ่งเป็นอีก 3 วิธีย่อย... หลักการก็คือถ้าเกิดการชนกัน มันก็จะหาช่องว่างใหม่...  
> **อันนี้เป็นสูตรที่เราต้องท่องนะครับ:**  
> $$h_i(x) = (\text{hash}(x) + f(i)) \pmod{\text{Table\_Size}}, \quad f(0) = 0$$  
> สมัยผมเรียน ผมก็ท่อง เพราะรู้ว่ามันออกสอบแล้วมันต้องใช้สูตร ก็ท่องไปเลย...  
> แล้วถ้าชนกัน เราจะไปหาช่องว่างใหม่ โดยเปลี่ยนค่า $i$ ไปเรื่อยๆ $h_0(x), h_1(x), h_2(x)...$  
> วิธีแรกคือ **Linear Probing (การตรวจสอบเชิงเส้น)** Linear แปลว่าเชิงเส้น ไม่ยกกำลัง ฟังก์ชันที่ง่ายที่สุดคือ $f(i) = i$... ถ้าชนช่องเดิม ก็บวก 1 ไปดูช่องถัดไป ชนอีกก็บวก 2 บวก 3 ไล่ไปเรื่อยๆ...  
> **ตอนสอบปลายภาค คุณจะเจอทรงแบบเนี้ย ให้ตารางมาตารางนึงว่างๆ แล้วให้คุณเอาเลขใส่ลงไป ไม่ว่าจะเป็นตัวเลขหรือชื่อคน แล้วแต่โจทย์แต่ละปี...**  
> ข้อดีของ Open Addressing คือ ข้อมูลจะใส่ลงไปใน Hash Table จริงๆ ไม่ต้องใช้ Linked List..."

### 1.3 ปัญหา Primary Clustering, Quadratic Probing และ Double Hashing
> "Linear Probing มีข้อเสียร้ายแรงคือ **Primary Clustering (กลุ่มก้อนหลัก)** ข้อมูลที่ชนกันจะไปกองรวมกันเป็นกลุ่มยาวๆ ทำให้ประสิทธิภาพการค้นหาช้าลงเรื่อยๆ...  
> เขาจึงพัฒนาวิธีที่สอง คือ **Quadratic Probing (การตรวจสอบกำลังสอง)**:  
> $$f(i) = i^2$$  
> ถ้าชนครั้งแรก ($i=1$) ขยับ $+1^2 = +1$, ชนครั้งที่สอง ($i=2$) ขยับ $+2^2 = +4$, ชนครั้งที่สาม ($i=3$) ขยับ $+3^2 = +9$... วิธียี้ช่วยกระจายข้อมูลไม่ให้ติดกันเป็นพรืด แต่ยังมีโอกาสเกิด **Secondary Clustering (กลุ่มก้อนรอง)**...  
> วิธีที่ดีที่สุดในการแก้ปัญหากลุ่มก้อนคือ **Double Hashing (การแฮชซ้ำสอง)**:  
> $$f(i) = i \times \text{hash}_2(x)$$  
> โดยฟังก์ชัน $\text{hash}_2(x)$ ต้องไม่ให้ผลลัพธ์เป็น 0 และขนาดของ Table Size ต้องเป็นจำนวนเฉพาะ (Prime Number) เสมอ เพื่อให้การข้ามครอบคลุมทุกช่องในตาราง..."

## 2. สรุปเปรียบเทียบกลยุทธ์การแก้ปัญหาการชน (Collision Resolution Strategies)

| วิธีการ (Method) | นิยามของฟังก์ชัน $f(i)$ | ลำดับการขยับเมื่อชน | ข้อดี | ข้อเสีย / ปัญหา |
| :--- | :--- | :--- | :--- | :--- |
| **Separate Chaining** | ไม่ใช้ $f(i)$ (ใช้ Pointer) | ต่อยาวเป็น Linked List ในช่องนั้น | ใส่ข้อมูลได้ไม่จำกัด ช่องไม่เต็ม | เปลืองหน่วยความจำ Pointer, ช้าในการ Traversal |
| **Linear Probing** | $f(i) = i$ | $+1, +2, +3, +4, \dots$ | คำนวณง่าย ไม่ซับซ้อน | เกิด **Primary Clustering** ก้อนข้อมูลกระจุกตัว |
| **Quadratic Probing** | $f(i) = i^2$ | $+1, +4, +9, +16, \dots$ | ลดปัญหาก้อนข้อมูลติดกัน | เกิด **Secondary Clustering**, อาจหาช่องว่างไม่เจอถ้าตารางเกิน 50% |
| **Double Hashing** | $f(i) = i \times \text{hash}_2(x)$ | $+1\cdot h_2, +2\cdot h_2, +3\cdot h_2, \dots$ | กระจายข้อมูลได้ดีที่สุด ไม่มี Clustering | ต้องคำนวณ Hash Function สองรอบ |

## 3. จุดสำคัญที่อาจารย์แง้มไว้สำหรับข้อสอบปลายภาค (Exam Tips)
1. **ตารางแฮชปลายภาค:** อาจารย์จะให้ตารางเปล่าระบุขนาด เช่น $\text{Table\_Size} = 10$ หรือ $11$ พร้อมชุดข้อมูล ให้จำลองการใส่ข้อมูลลงในตารางทีละตัวตามลำดับ
2. **การ Mod ด้วยขนาดตาราง:** ตำแหน่งทุกครั้งต้อง Mod ด้วย $\text{Table\_Size}$ เสมอ เช่น $15 \pmod{10} = 5$
3. **การแสดงวิธีทำ:** ต้องเขียนแสดงการคำนวณรอบที่ชน เช่น เมื่อ $i=0$ ชน ให้เขียนสูตร $i=1$ และแสดงช่องใหม่ให้ชัดเจน
